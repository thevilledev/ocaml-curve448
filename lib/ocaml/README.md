# OCaml backend

[Documentation](../../docs/README.md) · [Design](../../docs/design.md)

The default `curve448.ocaml` implementation, written in OCaml only. It was
written for this project from RFC 7748, RFC 8032, FIPS 202 and the formulas of
Hisil, Wong, Carter and Dawson, and contains no third-party code. It shares no
code with the C backend in `lib/c/native/`; the two agree on every test and
differential input.

| File | Origin | Contents |
| --- | --- | --- |
| `fe448_kernels.ml` | generated by `tools/gen_fe448_ocaml.py` | Field multiplication and squaring (192 and 108 limb products in unboxed `int64` locals), addition, subtraction, multiplication by a small constant, and the carry of decoded limbs |
| `fe448.ml` | hand-written | Field elements: encoding, constant-time selection and swap, inversion and square-root chains |
| `keccak.ml` | generated by `tools/gen_keccak_ocaml.py` | Keccak-f[1600], unrolled |
| `shake256.ml` | hand-written | The SHAKE256 sponge |
| `sc448.ml` | hand-written | Arithmetic modulo the edwards448 group order L, signed radix-16 recoding |
| `table448.ml` | generated by `tools/gen_tables.py --ocaml` | d, the base point, and the fixed-base table |
| `ge448.ml` | hand-written | Complete edwards448 formulas, point encoding, constant-time scalar multiplication |
| `backend.ml` | hand-written | X448, Ed448 and Ed448ph, and the internal test hooks |

## Requirements

OCaml 4.14 or later with 63-bit integers, that is a 64-bit native or bytecode
runtime. `Fe448` checks `Sys.int_size` when the library is initialised and
fails otherwise, so a 32-bit or js_of_ocaml build stops instead of computing
wrong results.

## Generated code

The generators are the source of truth for the generated files; CI fails if a
committed file differs from their output.

```sh
python3 tools/gen_fe448_ocaml.py > lib/ocaml/fe448_kernels.ml
python3 tools/gen_keccak_ocaml.py > lib/ocaml/keccak.ml
python3 tools/gen_tables.py --ocaml > lib/ocaml/table448.ml
```

- `gen_fe448_ocaml.py` proves by interval arithmetic that no intermediate of
  any kernel leaves the 63-bit integer range and that every output is tight
  (limbs at most 2^27 + 2^5 in absolute value), and evaluates each kernel on
  random and extreme inputs with Python integers, checking the results modulo
  p.
- `gen_keccak_ocaml.py` derives the rho offsets, pi positions and round
  constants from the algorithms of FIPS 202 rather than from tables, and
  checks its reference permutation against `hashlib.shake_256` before
  emitting code.
- `gen_tables.py` computes the tables with Python integers; the test suite
  recomputes every table entry with an independent Zarith model.

`docs/design.md` describes the representation and the constant-time
approach, and `compiler/README.md` the check of the compiled kernels.
