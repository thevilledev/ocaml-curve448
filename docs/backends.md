# Choosing a backend

[Documentation](README.md) · [Project home](../README.md)

The API is implemented twice, with the same algorithms and the same
behaviour, and the test suites run against both:

| | `curve448.ocaml` (default) | `curve448.c` |
| --- | --- | --- |
| Written in | OCaml only | C, called through `[@@noalloc]` externals |
| Field arithmetic | generated kernels, proved correct and overflow-free in Lean ([formal](../formal/README.md)) | [fiat-crypto](https://github.com/mit-plv/fiat-crypto), formally verified |
| Third-party code | none | fiat-crypto, and parts adapted from BoringSSL and tiny_sha3 |
| Needs | 64-bit OCaml | also a 64-bit GCC or Clang |
| X448, Ed448 sign, Ed448 verify (Apple M1 Pro) | 374, 147, 520 µs | 130, 64, 203 µs |
| The same on x86-64 (AMD Ryzen AI 9 HX PRO 370) | 225, 91, 328 µs | 93, 48, 152 µs |

The pure OCaml implementation is the default and adds no C stubs of its own.
The opam package builds both available backends, and its RNG dependency also
uses C; installing the package therefore needs the usual OCaml C toolchain.
The C implementation has formally verified field arithmetic; see the
[performance measurements](performance.md) for the speed comparison.

Dune chooses the implementation when it links an executable. Depending on
`curve448` selects `curve448.ocaml`; to use the C implementation, add
`curve448.c` to the executable's libraries:

```dune
(executable
 (name server)
 (libraries curve448 curve448.c mirage-crypto-rng.unix))
```

Libraries should depend on `curve448` only, so that the final executable can
choose. With ocamlfind instead of dune, the `curve448` package contains only
the interface; link `curve448.ocaml` or `curve448.c` explicitly.

## Implementation overview

- **OCaml.** Field elements are 16 signed 28-bit limbs. Multiplication,
  squaring, addition, subtraction and multiplication by a small constant are
  straight-line kernels generated by `tools/gen_fe448_ocaml.py`, which proves
  by interval arithmetic that no intermediate overflows; products are computed
  in unboxed `int64` locals. Keccak-f[1600] is generated from FIPS 202 by
  `tools/gen_keccak_ocaml.py`. Scalar arithmetic, the X448 ladder and the
  group code are hand-written ([OCaml backend notes](../lib/ocaml/README.md)).
- **C.** Field arithmetic modulo 2^448 - 2^224 - 1 is fiat-crypto's formally
  verified code, vendored unmodified from release v0.1.6; scalar arithmetic,
  SHAKE256, the X448 ladder and the group code are hand-written C
  ([C backend notes](../lib/c/native/README.md)).
- **Both** use complete edwards448 formulas and constant-time fixed-base
  (precomputed table) and variable-base scalar multiplication, for
  verification too, and avoid secret-dependent branches and memory access.
  Valgrind memcheck with secrets marked undefined finds no secret-dependent
  branch or memory access in these paths for GCC and Clang builds of the C
  backend, and for OCaml 4.14 and OCaml 5 builds of the OCaml backend, on
  aarch64 and x86-64 Linux (OCaml 5 on x86-64 only); the compiled OCaml
  kernels are also checked for branches and allocation. See
  [security policy](../SECURITY.md) for the limits.

[Design](design.md) explains the design and its trade-offs.
