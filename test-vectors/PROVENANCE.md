# Test-vector provenance

[Documentation](../docs/README.md) · [Testing](../docs/testing.md)

Every fixture in this directory comes from a pinned, immutable source or is
reproducible with a script in `tools/`. Fixtures are not refreshed from moving
branches; a change must cite its source revision and update this file.

## RFC 7748 and RFC 8032

`rfc7748.json` and `rfc8032.json` are extracted from the RFC text files by
`tools/extract_rfc_vectors.py`, which strips pagination, validates every
length and fails unless it finds exactly the expected vectors.

| Source | SHA-256 of the text |
| --- | --- |
| <https://www.rfc-editor.org/rfc/rfc7748.txt> | `279ca0ecc5e92e2962e27b846986aeb74729d9dd34bd4a04a362f80dcb596ad3` |
| <https://www.rfc-editor.org/rfc/rfc8032.txt> | `ed63657ff389301282b169b0abde9b5dd2c7e4d524fdfa5da6ff3094fc93c4c3` |

- RFC 7748, section 5.2: both X448 function vectors and the iterated vectors
  after 1, 1,000 and 1,000,000 iterations (the last runs only with
  `CURVE448_SLOW_TESTS=1`).
- RFC 7748, section 6.2: the X448 Diffie-Hellman vector.
- RFC 8032, section 7.4: all nine Ed448 vectors, including the one with a
  context; section 7.5: both Ed448ph vectors.

```sh
curl -O https://www.rfc-editor.org/rfc/rfc7748.txt
curl -O https://www.rfc-editor.org/rfc/rfc8032.txt
python3 tools/extract_rfc_vectors.py rfc7748.txt rfc8032.txt test-vectors
```

## Wycheproof

`wycheproof/x448_test.json` (510 tests, schema `xdh_comp_schema_v1.json`) and
`wycheproof/ed448_test.json` (87 tests, schema `eddsa_verify_schema_v1.json`)
are copied unmodified from `testvectors_v1/` of
[C2SP/wycheproof](https://github.com/C2SP/wycheproof) at commit
[`3fa63dd0344abb611f1fb1d77e119938603ea230`](https://github.com/C2SP/wycheproof/tree/3fa63dd0344abb611f1fb1d77e119938603ea230/testvectors_v1).

| File | SHA-256 |
| --- | --- |
| `x448_test.json` | `0f8f7199dbd47d1805cb9b13dfb29c207406bc786827bfd9ba7b73374b830fe5` |
| `ed448_test.json` | `3b3c7995853deb2fbbb49fba0fd292f314dc081f9154bd33252f294ca211289a` |

The test asserts `numberOfTests` so that no case is skipped silently. X448
expectations: `valid` cases must produce the shared secret; `acceptable` cases
must produce it, except the `ZeroSharedSecret` cases, which must fail with
`` `Low_order ``; `invalid` (`PublicKeyTooLong`) cases must fail with
`` `Invalid_length ``. Ed448: `valid` must verify and `invalid` must not.

The same commit also provides `x448_asn_test.json`, `x448_pem_test.json` and
`x448_jwk_test.json`. They test ASN.1, PEM and JWK key parsing, which this
library does not implement, so they are not included.

## RFC 9180 DHKEM(X448, HKDF-SHA512)

`rfc9180-dhkem-x448.json` holds the 32 vectors with `kem_id = 0x0021` (all four
modes, both KDFs and all AEADs) from the CFRG HPKE repository at commit
[`5f503c564da00b0687b3de75f1dfbdfc4079ad31`](https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/5f503c564da00b0687b3de75f1dfbdfc4079ad31/test-vectors.json)
(SHA-256 `61fc662f01996cd06d713dacf5e133167bd309a1f329442d53f1e21a47b3ede6`),
the source also pinned by ocaml-hpke. Only the fields the KEM consumes and
produces are kept. The test implements DeriveKeyPair, Encap/Decap and
AuthEncap/AuthDecap with this library's X448 and HKDF-SHA512 from `kdf`.

```sh
curl -O https://raw.githubusercontent.com/cfrg/draft-irtf-cfrg-hpke/5f503c564da00b0687b3de75f1dfbdfc4079ad31/test-vectors.json
python3 tools/extract_rfc9180_x448.py test-vectors.json test-vectors/rfc9180-dhkem-x448.json
```

## SHAKE256

`shake256.json` (135 vectors) was generated by `tools/gen_shake256_vectors.py`
with Python 3.14.7 `hashlib` backed by OpenSSL 3.6.4. Message and output
lengths straddle the 136-byte rate. The test additionally pins the published
SHAKE256 digest of the empty string.

## OpenSSL key and certificate files

`openssl/` holds files produced by the OpenSSL 3.6.4 command-line tool. The
keys exist only for these tests.

```sh
openssl genpkey -algorithm ed448 -outform DER -out ed448-key.der
openssl req -x509 -new -keyform DER -key ed448-key.der -outform DER \
  -out ed448-cert.der -days 36500 -subj "/CN=curve448 test certificate"
openssl genpkey -algorithm x448 -outform DER -out x448-alice.der
openssl genpkey -algorithm x448 -outform DER -out x448-bob.der
openssl pkey -inform DER -in x448-alice.der -pubout -outform DER -out x448-alice-pub.der
openssl pkey -inform DER -in x448-bob.der -pubout -outform DER -out x448-bob-pub.der
openssl pkeyutl -derive -keyform DER -inkey x448-alice.der \
  -peerform DER -peerkey x448-bob-pub.der -out x448-shared.bin
```

The test verifies the self-signed certificate's Ed448 signature over its
`tbsCertificate`, checks that the PKCS #8 seed yields the certificate's key and
a byte-identical signature, and checks the X448 public keys and derived secret.

## Differential corpus

`differential/openssl-circl.json` (383 cases) records the answers of OpenSSL
3.6.4 and Cloudflare CIRCL v1.6.3 to requests generated by
`tools/differential/run.sh --count 24 --seed 448`. See
[`docs/interoperability.md`](../docs/interoperability.md) for the categories
and the documented differences.

```sh
tools/differential/run.sh --count 24 --seed 448 \
  --output test-vectors/differential/openssl-circl.json
```
